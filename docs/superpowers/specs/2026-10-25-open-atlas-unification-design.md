# 오픈 아틀라스 전체 디자인 통일 설계

## 의도

`Dev Sky Archive`를 첫 보물지도부터 항구, 박물관, 프로젝트 전시까지 하나의 탐방형 게임 세계로 보이게 만든다. 현재 지도 바깥의 물결형 프레임이 화면을 한 번 더 가두고, 고밀도 지도 일러스트와 픽셀 게임 월드 사이의 시각 언어가 끊겨 보이므로, 지도는 화면 전체에 펼치고 모든 화면이 같은 팔레트·명판·잉크 질감·상호작용 규칙을 공유하도록 재구성한다.

## 목표

- 첫 화면은 별도의 카드나 물결형 테두리 없이 보물지도 자체가 화면을 채우는 오픈 아틀라스가 된다.
- 지도 위 랜드마크는 지도에 이미 그려진 건물·항구·배와 자연스럽게 결합하고, 이름표는 같은 종이/잉크 명판 규칙을 사용한다.
- 호버와 포커스는 지도 선화가 밝아지고 짧은 잉크 강조가 생기는 정도로 표현해 지도 그림을 덮지 않는다.
- 지도 → 항해 → 섬 월드 → 박물관 → 프로젝트 문서가 `양피지 베이스 + 짙은 갈색 잉크 + 녹슨 붉은 포인트 + 금색 안내`라는 공통 언어로 이어진다.
- 게임 화면에서는 HUD를 이동·현재 위치·문서 확인만 남기고, 지도 화면에서는 불필요한 패널과 장식을 제거한다.
- 화면 전환은 “다른 페이지로 이동”이 아니라 지도에서 해당 장소로 확대 진입하는 흐름으로 느껴진다.

## 비목표

- 3D 섬 월드나 외부 이미지 에셋을 다시 도입하지 않는다.
- 프로젝트 데이터 구조, GitHub 레포 인벤토리, J/E 문서 상호작용을 이번 변경의 이유 없이 바꾸지 않는다.
- 제공된 보물지도 일러스트를 전부 픽셀 스타일로 다시 그리지 않는다. 지도 고밀도 선화는 기준 자산으로 유지한다.

## 실패로 보는 것

- 지도 위에 다시 별도의 큰 프레임, 물결 테두리, 장식 패널을 겹쳐 답답해지는 것
- 랜드마크와 무관한 가짜 섬·도형·카드를 추가하는 것
- 지도는 갈색 선화인데 게임 HUD만 차가운 네이비 카드로 떠 보이는 것
- 화면마다 다른 명판 모양과 폰트 규칙을 쓰는 것
- 에셋 수만 늘고 항구→박물관→전시라는 동선의 이유가 설명되지 않는 것

## 선택한 접근

### 1. 오픈 아틀라스 — 선택

지도 이미지가 뷰포트의 주인공이 되도록 배치하고, 바깥 CSS 프레임은 제거한다. 지도 자체에 포함된 종이 가장자리와 잉크 질감만 남긴다. 자연 지도 위에는 최소한의 HTML 랜드마크 핫스팟을 올리고, 이름표는 지도 색상에 섞이는 반투명 양피지 명판으로 통일한다. 게임 월드는 지도에서 확대된 장소라는 설명을 유지하기 위해 같은 갈색·금색·붉은색을 픽셀 에셋과 HUD에도 재사용한다.

장점은 사용자가 제공한 지도 분위기를 보존하면서 답답함을 즉시 줄이고, 지도에서 게임으로 넘어가는 개연성을 가장 적은 구조 변경으로 만들 수 있다는 점이다.

### 2. 액자형 지도 — 제외

지도 주변에 나무 액자나 큰 종이 프레임을 두는 방식이다. 박물관 분위기는 강해지지만 현재 사용자가 지적한 “테두리 안에 갇힌 느낌”을 반복하고, 화면 전체가 지도라는 목표와 맞지 않는다.

### 3. 전면 픽셀 지도 — 제외

첫 화면까지 픽셀 타일로 다시 그리는 방식이다. 게임과의 표면 통일은 쉽지만, 사용자가 선택한 고밀도 보물지도 일러스트의 개성과 탐방 시작점으로서의 역할을 잃는다.

## 화면별 규칙

### 보물지도

- 지도는 `full-bleed`로 화면을 채우고 별도 물결형 외곽 분할을 사용하지 않는다.
- 랜드마크는 실제 지도 위 건물·항구·배의 중심에 붙인다.
- 라벨은 짙은 갈색 잉크, 낮은 불투명도의 양피지, 얇은 갈색 선으로 통일한다.
- 호버/포커스는 원형 링이나 큰 카드 대신 작은 잉크 번짐, 라벨 대비 상승, 미세한 확대만 사용한다.
- 안내 문구는 화면 가장자리의 작은 양피지 탭 하나로 제한한다.

### 항해 화면

- 지도와 같은 종이 색·갈색 선·붉은 경로를 사용한다.
- 경로는 실제 선택한 랜드마크를 연결하고, 이동 중인 배가 그 경로를 따라간다.
- 중앙 카드 하나만 유지하고 주변 장식은 줄여 이동 자체를 강조한다.

### 섬 월드와 박물관

- 섬 월드는 같은 팔레트의 픽셀 타일과 오브젝트를 사용하되, HUD 명판과 상호작용 색은 지도 라벨과 공유한다.
- 항구는 도착·출발, 길은 박물관으로 유도, 박물관 계단과 안내 NPC는 입장 이유를 제공한다.
- 박물관 내부는 중앙 통로와 양쪽 전시실을 분리해 “걷다가 전시를 발견하는” 구조로 만든다.
- 전시대 이름표, J 상호작용 토스트, 도슨트 모달의 강조색은 동일한 녹슨 붉은색/금색 계열을 사용한다.

## 구현 범위

- `src/styles.css`: 지도 외곽 프레임·물결형 분할 제거, full-bleed 지도 레이아웃, 공통 명판·포커스·호버 토큰 정리
- `src/treasure-map.js`: 랜드마크 핫스팟과 지도 중심 좌표를 실제 일러스트 위치에 맞춰 조정
- `src/app.js`: 지도→항해→섬 월드에서 공통 팔레트와 전환 문구를 사용하고, 불필요한 월드 HUD 요소를 제거
- `assets/`: 새 에셋이 필요하면 현재 로컬 SVG 책임 폴더에만 추가하며 외부 이미지나 AI 이미지 생성은 사용하지 않음
- `tests/`: full-bleed 지도, 명판 스타일, 키보드/포인터 진입, 기존 프로젝트 문서 흐름 회귀 검증 추가
- `README.md`와 디자인 시스템 기록: 지도와 게임 월드가 하나의 오픈 아틀라스 규칙을 공유하도록 문서화

## 완료 기준

1. 첫 화면에서 큰 물결형 외곽 테두리 없이 지도 일러스트가 뷰포트를 채운다.
2. 지도 랜드마크 라벨이 지도 속 대상에 붙어 있고, 호버/포커스 상태가 지도 그림을 가리지 않는다.
3. 지도·항해·섬·박물관 화면에서 팔레트와 명판 언어가 일관된다.
4. 개인 프로젝트 섬에 들어가 항구에서 시작하고, 박물관으로 이동해 J로 문서를 여는 기존 흐름이 유지된다.
5. 모바일/좁은 뷰포트에서도 지도와 핫스팟이 잘리지 않고 키보드 사용자는 포커스 상태를 확인할 수 있다.
6. 전체 테스트와 `git diff --check`, 로컬 브라우저 검증이 통과한다.

## 구현자가 결정할 부분

- 지도 원본 이미지의 가장자리 질감은 유지하되, CSS로 추가되는 바깥 프레임만 제거한다.
- 지도 위 안내 탭의 정확한 위치와 문구는 랜드마크가 가려지지 않는 지점으로 조정한다.
- 기존 픽셀 에셋을 재색상할 때 새 색을 무작정 늘리지 않고 공통 팔레트 토큰으로 제한한다.
