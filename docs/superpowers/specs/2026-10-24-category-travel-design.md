# Category Travel Design

## Intent

하늘맵에서 카테고리를 클릭했을 때 바로 화면이 바뀌는 대신, 플레이어가 현재 위치에서 목적지까지 실제로 이동하는 느낌을 준다. 이동 경로는 카테고리 그래프에서 BFS로 계산하고, 최단 경로의 길이를 항해 시간과 화면 정보에 반영한다.

## Goals

- 마지막으로 방문한 카테고리를 현재 위치로 기억한다.
- 현재 위치와 목적지 사이의 최단 경로를 BFS로 계산한다.
- 경로의 hop 수에 비례해 항해 시간이 달라진다.
- 항해 중 전용 화면에 출발지, 목적지, 진행률, 경로, 목적지 한 줄 Tip을 보여준다.
- 항해가 끝나면 기존 2D 섬 화면으로 진입한다.
- 새 화면도 현재 보물지도와 같은 종이/잉크 세계관을 유지한다.
- 실제 프로젝트 데이터의 `description` 또는 단일 프로젝트의 `summary`를 Tip으로 사용한다.

## Non-goals

- 새 이미지 생성이나 외부 게임 에셋 도입
- WASD 섬 내부 이동 로직 변경
- 프로젝트 전시 화면의 정보 구조 변경
- 실제 네트워크 기반 이동이나 서버 저장

## Chosen approach

7개 카테고리를 노드로 하는 명시적 그래프를 둔다. 프로필은 여러 카테고리와 연결된 허브이고, 개인·팀·자료·작업·스터디·대외활동은 실제 탐방 흐름처럼 연결한다. `findShortestPath`는 BFS로 이웃을 큐에 넣고 방문 집합을 사용해 최단 경로를 반환한다.

현재 위치가 없으면 첫 목적지까지는 즉시 입장한다. 섬에서 하늘맵으로 돌아오면 해당 섬이 다음 이동의 출발지가 된다. 같은 섬을 다시 클릭하면 불필요한 로딩 없이 입장한다.

항해 시간은 `1800ms + 추가 hop당 900ms`에 `6500ms` 최대값을 적용한다. 이동 화면을 읽을 수 있을 만큼 길게 유지하되, 탐방 흐름을 끊을 정도로 오래 기다리지는 않게 한다. reduced motion 설정에서는 0ms로 건너뛴다.

항해 화면은 실제 `treasure-map-etched.png`를 전체 배경으로 재사용한다. 그래프 경로의 각 카테고리 좌표를 지도 위 잉크 경로와 출발/경유/도착 스탬프로 표시하고, 목적지의 지도 랜드마크 유형에 따라 `해상 항로`, `육상 항로`, `정착지 항로`, `중심 항로`라는 항해 컨셉을 선택한다. 새 AI 이미지나 단순 도형 일러스트를 추가하지 않는다.

## State and UI

- `mapLocationId`: 하늘맵에서 마지막으로 방문한 카테고리
- `travel`: 현재 항해의 path, origin, destination, duration, tip
- `screen`: `sky`, `travel`, `island`, `project`

항해 화면은 별도 full-screen section이다. 현대적인 흰색 모달 대신 지도 종이 색, 잉크 선, 작은 나침반, 점선 경로, 진행 막대를 사용한다. 텍스트는 다음처럼 짧고 읽기 쉽게 구성한다.

```text
항해 중
자료  →  개인 프로젝트
최단 경로 02 / 02
TIP  혼자 끝까지 밀어붙인 프로젝트
```

화면 전환 중에는 목적지 버튼을 다시 누를 수 없게 하고, 완료 후 목적지 섬으로 진입한다. `Escape`와 기존 뒤로가기 동작은 항해가 끝난 뒤에만 적용한다.

## Acceptance criteria

- 자료에서 개인 프로젝트를 클릭하면 개인 프로젝트까지의 BFS 경로가 계산된다.
- 경로 hop 수가 다른 목적지는 다른 duration을 가진다.
- 항해 화면에서 출발지/목적지/Tip/진행률이 보인다.
- 진행률 완료 후 기존 섬 화면이 열린다.
- 첫 진입과 같은 위치 재진입에는 긴 가짜 로딩이 없다.
- 기존 지도 hover와 2D 섬 탐방 테스트가 계속 통과한다.
